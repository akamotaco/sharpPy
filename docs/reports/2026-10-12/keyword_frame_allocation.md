# 112차: 함수 호출 비교와 키워드 전달 프레임 제거

108차(5e03854)와 109차(8098043)를 git archive에서 별도로 빌드하여 비교했다.
10만 회, 표본 15개, 교차 3쌍, CPU mask 0x4, tiering off다.
일반 호출 프로세스 중앙값의 중앙값은 91.1171→90.3135 ms,
범위는 85.5664–92.3099 / 87.0659–91.1406 ms로 겹쳤다.
할당량은 양쪽 70,705,232 B로 같다. 덧셈 대조군은 34.3357→34.0522 ms.
이 실험은 기존 105차 대비 +3.4% 관측을 109차의 회귀로 단정할 근거가
없음을 보여준다. 과거 관측의 단일 원인을 확정한 것은 아니다.

별도 코드 분석에서 CreateWithKwargs가 키워드 이름 전달만을 위해 코드 객체,
프레임, 지역 스코프를 만드는 것을 확인했다. CPython ceval.c의 kwnames처럼
이름 tuple을 인자 바인더에 직접 전달한다. 두 임시 List도 정확한 크기 배열로
대체했다. 인자 평가와 매개변수 바인딩 순서, 지연 실행 시점은 유지한다.
실제 호출자가 아닌 kwargs_holder가 scope chain에 들어가는 부작용도 없어진다.

1만 회, 표본 15개, 교차 3쌍의 변경 전후 비교:

| workload | 이전 ms | 이후 ms | 전체 할당 B |
|---|---:|---:|---:|
| keyword generator 생성/next | 71.1198 | 65.7582 | 41,522,384 → 24,482,384 |
| 일반 함수 호출 대조군 | 8.9102 | 8.6762 | 6,962,384 → 동일 |

대상 경로 약 7.5% 감소, 호출당 1,704 B 감소다. 일반 호출은 이 경로를
거치지 않으므로 그 시간 차이를 이 최적화의 효과로 주장하지 않는다.

인자 평가 이벤트, 일반/제너레이터/코루틴 실행 시점, 생성 뒤 기본값 변경,
closure를 CPython 3.12.15와 비교했다. Godot 소스 빌드와 기본 17개,
관련 2개 및 경로 5개 통과. 전체 회귀와 원시 측정은 round112-validation.json.

추가 검증 중 async generator __anext__가 awaitable 생성 시점에 본문을
실행하려다 실패하는 기존 문제를 발견했다. 속성만 확인하던 과거 검증의
범위 밖이었다. async_generator_execution_remaining.py로 보존하고
후속 6번 실행 검증에 포함한다. 해결되지 않은 실패를 기본 통과 목록에 넣지 않는다.
