# 성능 재평가와 비용 분리 (99차, 작업 6)

## 적용한 변경

int 하위 타입과 정확한 builtin 숫자의 비교는 공통 진입점에서 타입 조건을 확인한 뒤 바로 슬롯을 호출한다. 하위 타입 우선권이 불필요한 조합에서 ResolveComparison과 중복 타입 검사를 거치지 않는다. 사용자 결과·NotImplemented·오류와 C# 파생 타입의 virtual 재정의는 유지한다.

94차에서 등록한 여섯 int 비교 descriptor가 하위 클래스 TypeDict마다 복사되던 것도 제거했다. 이미 MRO로 조회하는 wrapper의 중복 저장이다. 클래스 1,000개 생성의 native 할당은 1,808,000→1,032,000B(-776,000B), 첫 비교 캐시 40,000B·반복 비교 0B는 같다.

한 인자 OSError 생성은 errno 해석을 하지 않는다. 이를 별도 경로로 분리해 일반 생성이 BigInteger 비교용 프레임을 거치지 않게 했다. JIT에서 기존 FromArguments는 885B, 추가 스택 예약 144B와 초기화가 있었고, 새 진입 함수는 PyType.CreateInstance 안에 인라인된다. 호출자 코드는 9,297→9,407B로 늘었으나 한 인자 경로는 errno helper를 호출하지 않는다. 2~5개 인자만 별도 helper에 넘기며 kwargs 오류와 Windows 정규화는 유지한다.

저장소 검토 중 32비트 perturb 값을 native 폭으로 자르는 처리를 명시했다. x64에서는 기존 연산과 같다. 50,000개 키로 작은/큰 인덱스 테이블 경계와 복사·삭제, 음수 native 해시를 회귀에 추가했다. 32비트 실행 자체는 검증하지 않았다.

## 측정

Release .NET 8.0.31, tiering 비활성, VM 10만 회·warmup 10·표본 15·교대 3쌍. 프로세스 중앙값들의 중앙값을 사용한다. `compare_runs.py`로 표본·DLL 해시·인자를 보존하며 `--affinity 0x4`는 자식 측정 프로세스만 같은 논리 CPU에 고정한다.

| 비교 workload (CPU 고정) | 수정 전 ms | 수정 후 ms | 해석 |
| --- | ---: | ---: | --- |
| int_subclass_compare | 139.8427 | 137.2967 | 약 -1.82%, 프로세스 중앙값 범위가 분리됨 |
| int_subclass_float_compare | 142.0879 | 139.6583 | 중앙값은 약 -1.71%이나 표본 범위가 겹침 |
| mixed_compare_small 대조군 | 139.3186 | 136.8790 | 범위가 겹쳐 개선으로 단정하지 않음 |

비고정 측정의 일반 integer/user 대조군도 범위가 겹친다. 모든 비교 workload의 할당은 동일하다. CPU 고정 측정의 90차 기준은 int 하위 타입 136.8232ms, int/float 137.0868ms다. 후자의 잔여 차이가 완전히 해소됐다고 주장하지 않는다.

예외 VM 측정은 일반 생성 96.3024→96.3071ms, fallback 72.8948→73.3149ms, winerror 88.0321→87.5462ms, ValueError 대조군 64.4546→64.7838ms다. 모두 범위가 겹치며 할당은 같다. VM 전체 개선은 주장하지 않는다.

직접 생성은 10만 회·warmup 5·표본 10·CPU 고정·역순 시작 교대 6쌍으로 추가 검증했다. OSError 한 인자 중앙값은 1.0609→0.91195ms(약 -14.0%). 일부 프로세스 범위가 겹치므로 이 비율을 VM 전체로 환산하지 않는다. 두 인자 OSError는 3.093325→3.09075ms, FileNotFoundError 한/두 인자는 0.962575→0.9478ms / 1.2345→1.232975ms다. 초기 세 쌍에서 보인 FileNotFoundError 두 인자 증가가 고정 CPU 여섯 쌍에서는 유지되지 않았다. native 생성의 할당은 모두 이전과 동일하다.

## 과거 85→86차 지연의 결론

당시 원본 DLL을 다시 사용했다. 비고정 VM 일반 생성은 98.3851→98.0048ms(-0.39%), CPU 고정에서는 98.9837→99.8278ms(+0.85%)였다. 과거 +2.72%와 같은 크기·방향의 안정된 증가를 확인하지 못했다. 값·범위·원시 표본을 모두 보존하며 불리한 표본을 제외하지 않았다.

85/86차 FromArguments 코드는 841→885B지만 한 인자 경로의 실행 분기와 144B 스택 초기화는 동일하다. 추가한 int 하위 타입 hash/eq 분기는 이 workload에서 실행되지 않는다. 새 hot path 분리는 두 버전 모두에 있던 비용을 줄인 것이다. 과거 증가의 단일 원인을 해결했다고 결론 내리지 않는다. 원인 미확정 항목은 계획 문서에 계속 남긴다.

## 최종 검증과 증거

- 기본 171개 통과: 출력 일치 166, 기존 변동 필드 정규화 3, native CLI 검사 2.
- Godot 소스 직접 포함 빌드 경고/오류 0, 기본 17개 + 관련 27개 출력 일치.
- native invalid operator 8개와 C# 하위 타입 비교 override 양방향 12개 통과.
- 클래스 중복 저장 제거 후 기능 전체를 재검증했다. VM 성능 표본은 그 직전 비교/예외 구현이며, 마지막 변경은 중복 클래스 dict 항목 제거다. 최종 native 할당·예외 probe와 기능 DLL 해시는 별도로 보존한다.

전체·Godot·native·교대 성능·과거 바이너리 재측정·JIT 원문은 `round99-validation.json`에 있다. 기능 결과를 우선하고, 보장되지 않는 시간 개선이나 미확정 원인 해결을 주장하지 않는다.
