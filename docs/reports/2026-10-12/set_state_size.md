# 126차: set 저장소 상태 크기

후속 3번의 작은 set 할당 개선이다. pop 탐색 위치와 공유 상태를 한 int에 저장한다.
CLR 배열 인덱스가 사용하지 않는 부호 비트를 공유 상태로 쓴다. CPython의 테이블
배치, probe, 비교 callback, pop 순서는 변경하지 않는다.

10,000회, 15 samples, 독립 3쌍, affinity 0x4, tiering off 측정:

| 작업 | 변경 전 ms | 변경 후 ms | 변경 전 할당 B | 변경 후 할당 B |
| --- | ---: | ---: | ---: | ---: |
| 작은 set 생성·변경 | 15.9853 | 15.9240 | 8,481,272 | 8,401,272 |
| copy | 9.1009 | 9.0970 | 3,051,328 | 2,971,320 |
| membership 대조군 | 5.4428 | 5.4285 | 803,216 | 803,208 |

저장소당 8B 감소했다. 모든 시간 범위가 겹쳐 실행 속도 향상은 주장하지 않는다.
이전 HashSet 구현 대비 작은 set 잔여 할당은 반복당 +216B다. 비교 dispatch 비용과
이 잔여 할당은 해결 완료로 분류하지 않는다.

CPython 3.12.15와 set 관련 4개 fixture 출력 일치. 공유 전 pop, 공유 후 양쪽 pop,
clear 후 pop을 크기 4/5/17/65로 추가 검증했다. Godot 소스 빌드 및 기본 검증,
관련 fixture 2개 통과. 원자료는 round126-validation.json에 보존한다.
