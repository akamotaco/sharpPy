# 정렬 프로토콜 (96차, 작업 3)

sorted와 list.sort를 같은 안정 정렬에 연결했다. CPython v3.12.15 listobject.c의 run 탐색·이진 삽입·powersort 병합 순서·gallop을 보존해 비교 callback 순서와 오류 후 permutation을 맞춘다. 임의 비교 결과는 Python 진리값으로 판정하고 예외를 원형대로 전달한다. reverse는 정렬 전후 반전으로 안정성을 보존한다. key 실행 중 원래 리스트는 비어 있으며 변경 시 ValueError, 이미 발생한 callback 예외는 우선 보존한다. C의 참조 카운팅·포인터 관리는 이식하지 않았다.

회귀는 최대 1,024개·네 입력 패턴·양방향 정렬의 전체 비교/진리값 호출 기록, 여러 비교 단계의 예외와 부분 결과, key 순서·안정성·mutation·재진입을 실제 CPython 3.12.15와 대조한다. 전체 166개 통과(출력 161, 변동 필드 3, native 2). 이후 작은 정렬의 임시 저장소를 줄인 변경은 대상 회귀와 Godot 전체 관련 검증으로 재확인했다. Godot 소스 포함 빌드와 기본 17개·관련 22개 통과.

성능: 93차 바이너리 대조군과 각 1,000회, warmup 10, 표본 10, 교대 3쌍, tiering 비활성. 큰 입력은 프로세스 중앙값 약 32.9→31.3ms, 이미 정렬된 입력 19.1→9.75ms. 작은 입력은 약 6.33→6.38ms로 범위가 겹쳐 개선을 주장하지 않는다. 1,000회 할당은 작은 입력 921,184→953,184B(+32B/회: callback에 노출할 임시 빈 리스트), 큰 입력 9,263,152→9,119,152B, 정렬된 입력 9,234,600→7,258,600B. 처음 구현의 작은 입력 +304B/회는 +32B/회로 줄였다. 새 의미를 보존하기 위한 잔여 할당을 숨기지 않는다.

`round96-validation.json`에 전체·최종 대상·Godot·성능 표본과 DLL 해시를 보존했다. `sort_workloads.py`는 재실행 가능한 workload다. 작업 4~6은 미완료다.
