# 큰 정수 문자열 파싱 (98차, 작업 5)

Int64로 축소하던 공통 파서를 임의 정밀도 정수 파서로 바꿨다. 일반 int의 문자열 변환과 int 하위 타입이 같은 경로를 쓴다. CPython 3.12.15 longobject.c와 실제 실행을 기준으로 부호·공백·진법 0/2~36·접두사·밑줄·Unicode decimal digit·base=0 선행 영·원문을 보존한 오류를 검증했다. non-power-of-two 입력에는 CPython 기본 4,300자리 제한을 적용한다. 런타임 sys 설정으로 이 제한을 변경하는 API는 별도 미구현 범위다.

십진 문자열은 검증 후 작은 값의 native 파싱을 먼저 시도하고 큰 값만 BigInteger 파서에 넘긴다. 다른 진법은 native 크기의 chunk를 모아 BigInteger 연산 횟수를 줄인다. 같은 초기화 함수에서 나중에 무조건 덮어쓰이던 오래된 Int64 __new__ 등록을 제거했다. 활성 생성자나 하위 타입 생성 경로를 새로 추가하지 않았다.

기본 회귀 171개 통과(출력 166, 변동 필드 3, native 2). 마지막 작은 값 fast path는 새 두 회귀와 Godot 검증으로 다시 확인했다. Godot 소스 포함 빌드, 기본 17개·관련 27개 통과. 80~300자리·음수·여러 진법과 Unicode, 명시적 int.__new__의 타입 보존 및 4,300/4,301자리 경계를 포함한다.

작은 문자열 하위 타입 생성 1만 회, warmup 10, 표본 10, 교대 3쌍, tiering 비활성: 프로세스 중앙값 약 55.05→55.37ms로 범위가 겹친다. 할당은 양쪽 12,721,184B로 같다. 첫 BigInteger-only 구현의 추가 104B/회는 제거했다. 원래 실패하던 큰 문자열을 속도 개선의 대조군으로 쓰지 않았다. `round98-validation.json`에 전체·최종 대상·Godot·성능 결과를 보존했다. 작업 6이 남는다.
