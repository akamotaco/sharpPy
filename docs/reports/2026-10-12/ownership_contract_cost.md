# 118차: 소유권 계약 후보의 비용 — 자동 해제 미해결

114차의 실패 목록을 다시 설명하는 대신 `--ownership-cost-probe`로 구조 후보의
비용을 측정했다. 런타임과 분리된 합성 실험이며 Python 참조 추적을 구현한 것이 아니다.
Release, tiering off, 10만 개/회, warmup 3, 표본 11, 한 프로세스다.

| 후보 | 중앙값 ms | 할당 B |
|---|---:|---:|
| 참조 필드 하나인 객체 생성 | 0.3106 | 2,400,000 |
| 여기에 소유자 counter 추가 | 0.4998 | 3,200,000 |
| 별도 ConditionalWeakTable 등록 | 9.6522 | 10,044,368 |
| 필드 acquire/release 쌍 | 0.2754 | 0 |
| 별도 테이블 acquire/release 쌍 | 1.2051 | 0 |

이 배치에서는 필드 추가가 객체당 8B를 늘린다. 별도 테이블은 기본 객체 배치를
유지하지만 등록/조회 비용이 크다. 실제 모든 PyObject에 대한 크기 증가나 VM
속도 변화로 일반화하지 않는다. 단일 프로세스 시간은 후보 선별용이다.
두 후보 모두 처리 후 소유자 수가 원래 값인지 검사한다.

후속 구현 계약은 다음과 같다.

1. 스택의 take와 drop을 구분한다. Pop의 소유권 이전 시 release하면 호출 인자,
   STORE_FAST, 컨테이너 삽입 중 객체를 너무 일찍 해제한다.
2. 교체는 새 참조 취득 → 저장 → 옛 참조 반납 순서여야 한다. callback 재진입 시
   새 상태가 보여야 하며 자기 대입은 해제를 일으키지 않는다.
3. 컨테이너 자체의 마지막 소유자 반납이 자식 반납으로 이어져야 한다.
   view만 추적하면 tuple/list/closure 소멸 경계를 해결할 수 없다.
4. 프레임 소유권은 함수 반환과 suspended generator, 외부 f_locals/frame 참조를
   구분한다. 예외 unwind에서도 임시 소유 참조를 반납한다.
5. 호스트로 나가는 반환값은 명시적 owned handle, 호출에 빌려주는 값은 borrowed
   계약이 필요하다. 공개 배열/Dictionary 직접 쓰기를 계속 허용하면서 정확한
   소유권을 보장할 수 없다. 2번 호스트 저장소 작업과 연결되는 경계다.
6. 순환 수거는 비순환 마지막 참조 해제와 분리한다. CLR finalizer/강제 GC는
   Python 마지막 참조의 시점을 대체하지 않는다.

현재 성능 근거로 모든 객체에 counter나 weak table을 붙이는 변경을 채택하지
않았다. 대상 컨테이너와 호스트 API를 연결한 실험이 있어야 통합 여부를 결정할 수 있다.
런타임은 변경하지 않았다. CPython 3.12.15 재실행에서 마지막 소유권 9개 차이가
유지되고 live alias 회귀는 일치한다. **이 항목은 설계·비용 선별이며 자동 해제는
여전히 미해결이다.** 원시 결과는 round118-validation.json.
