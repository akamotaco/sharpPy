# 120차: 작은 set의 임시 테이블 할당 감소

set resize가 버리는 8-entry 배열 하나를 초기 테이블로 재사용한다.
공유 배열은 제외하며 key/hash를 모두 지운 뒤 Interlocked로 반환한다.
최대 한 배열만 보관하므로 사용자 객체를 붙잡거나 무제한 cache를 만들지 않는다.
CPython probing, 크기 전환, stored hash, COW copy 과정은 유지한다.

새 회귀는 작은 원본과 공유 복사본을 유지하면서 반복 resize/생성/clear를 수행한다.
비교 callback 안에서 원본을 resize한 뒤 새 set을 만들어 이전 배열을 재사용하는
재진입도 CPython 3.12.15와 비교했다. 기존 set 3개와 신규 회귀 모두 일치한다.
Godot 소스 빌드, 기본 17+관련 3개와 경로 5개 통과.

10,000회, warmup은 기존 하네스, 표본 15, 교차 3쌍, tiering off, affinity 0x4:

| 경로 | 이전/이후 ms | 이전/이후 할당 B |
|---|---:|---:|
| 작은 set 생성/추가/조회/삭제 | 15.9095 / 15.8880 | 10,001,272 / 8,481,272 |
| 64개 원소 복사 | 9.1513 / 9.1336 | 3,051,480 / 3,051,328 |
| membership 대조 | 5.4104 / 5.4548 | 803,368 / 803,216 |

대상 반복당 152B 감소하며 시간 범위는 모두 겹친다. 복사/대조의 152B 감소는
설정 시 초기 배열 하나의 차이이며 반복당 감소로 해석하지 않는다.
113차에 확인했던 이전 저장소 대비 +376B는 +224B로 줄었지만 완전히 없애지는 못했다.
일반 객체 수명 추적이나 GC 시점 반환을 도입하지 않았다.
원시 결과는 round120-validation.json. 전체 통합 회귀는 후속 6번에서 수행한다.
