# 2026-10-13: 반복된 부분 해결과 구조 복잡도 증가에 대한 판단 오류

## 책임과 범위

이 기록은 작업을 수행한 assistant의 오류를 남긴다. CPython 소스 부족이나 사용자의
요구 때문으로 돌리지 않는다. 사용자는 CPython 3.12의 관찰 가능한 과정·결과 일치와
최적화, 남은 1~6번 해결을 요청했다. assistant는 125~130차에 부분 수정 여섯 개를
커밋·푸시했으나 원래 문제들을 모두 해결하지 못했다. 미해결이라고 보고한 사실은
이러한 작업 진행 방식의 결함을 면제하지 않는다.

| 계획의 현재 상태가 여러 시점으로 분산됨 | 99~130차 기록에 여러 ‘현재’ 제목과 서로 다른 테스트 개수가 공존 | 계획 상단만 최신 상태로 유지하고 이전 단계는 명시적으로 이력으로 구분한다. |

CPython 소스를 읽었다는 사실만으로 구조가 타당해지는 것은 아니다. 해당 진입점에서
저장소, 조회, callback, 예외 및 해제까지 연결하고 SharpPy의 각 경로와 대응시켜야 한다.
동일한 처리를 두 경로에서 수행한다면 중복 유지의 이유를 증명하거나 통합해야 한다.

## 코드 증가에 대한 사실 확인

비교 범위는 ab1bb8554636974b338392f4e4ce2c7ad18bff18에서
45cf873f599fe844424d05a4fc72512a3666dce7까지, 최근 여섯 커밋이다.
`git diff --numstat ab1bb85 45cf873`의 물리적 줄 수이며 주석과 공백을 포함한다.

| 실행 코드 변경 | 순증 줄 수 |
| --- | ---: |
| namespace | 237 |
| 파일 IO | 120 |
| memoryview 정리 | 26 |
| warnings | 15 |
| set 상태 | 11 |
| 문자열 포맷 | 4 |
| 합계 | 413 |

실행 코드 분류는 docs/tests/benchmarks/tools를 제외한 변경 파일이다.
C# 소스는 Generated 및 위 경로를 제외하면 111,054 → 111,452줄(+398, 약 0.36%)이며,
나머지 15줄은 Lib/warnings.py다. 검증 JSON은 별도 +33,540줄, Markdown 문서는
순증 233줄이다. 큰 diff의 대부분은 원자료지만 이것이 실행 구조의 복잡도를 정당화하지 않는다.
반대로 늘어난 모든 줄이 불필요하다고 단정하지도 않는다. 문자열 포맷은 기존 파서를
제거하고 교체했으며, namespace가 실행 코드 순증의 약 57%를 차지한다.

CPython과의 전체 파일 줄 수 비교는 구현 범위, C/.NET 기반 기능, 생성 코드가 달라
효율성의 증거로 사용하지 않는다. CPython moduleobject.c의 md_dict 직접 사용과
SharpPy namespace의 추가 cache/adapter처럼 실제 책임과 경로를 비교해야 한다.

## 다음 단일 작업: namespace 경로 정리

1. PyNamespace, PyGlobalsDict, module/frame/function globals 및 raw Dictionary adapter의
   실제 호출자를 열거한다. authoritative 저장소, 파생 cache, legacy 원본의 관계를 그린다.
2. CPython 3.12.15 revision e848e4b09ca4bc67c0041c9ce7526dae471d4c36의
   moduleobject.c, dictobject.c 및 전역 조회 경로와 대응시킨다. variation은 별도로 적는다.
3. 기존 host 19개 검사와 namespace callback·재진입·live view·iterator·copy 회귀를
   고정한다. 기존 raw adapter에서 표현하지 못한 삭제/재삽입 이력도 재현하고,
   새 API 경로의 통과 결과를 기존 API 문제의 해결이라고 바꿔 쓰지 않는다.
4. 필요한 호스트 계약에 따라 중복 경로를 교체·통합한다. 기존 호출자의 이전과
   제거할 코드를 함께 검토한다. 단순히 새 adapter를 하나 더 얹지 않는다.
5. 동일 API의 전후 과정·출력을 비교하고 VM read/update, Copy, 대조군 시간·할당을
   측정한다. API 이전 비교는 별도로 표시한다. .NET과 Godot 소스 빌드·실행을 확인한다.

완료는 원래 재현 사례의 해결, 불필요한 중복 경로 제거, 성능 비용의 검증으로 판단한다.
경로를 남겼다면 각 경로의 독립적인 필요성을 설명할 수 있어야 한다. 필요한 경로의 수를
무조건 하나로 만드는 것도 목표는 아니다. 완료 조건에 미달하면 그 이유를 기록하고
namespace를 진행 중으로 유지한다. 후속 항목 추가나 커밋 수 증가로 대체하지 않는다.

이 문서 갱신은 코드 수정이나 기존 실패 해결이 아니다. 현재 구현 상태는
[평가 계획](../../evaluation_and_performance_plan.md) 상단을 따른다.
